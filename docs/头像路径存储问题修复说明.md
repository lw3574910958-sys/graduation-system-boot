# 头像路径存储问题修复说明

## 问题描述

在 graduation-system 项目中，头像上传后存入数据库的是完整的绝对路径（如 `http://127.0.0.1:8080/files/avatar/2011317294235017217/avatar.jpg`），这会导致：

1. **开发环境问题**：URL 中包含本地开发服务器地址（`127.0.0.1:8080`）
2. **生产环境问题**：部署到生产环境后，头像 URL 仍然指向开发环境，导致无法访问
3. **可移植性问题**：数据库中的数据无法在不同环境间迁移

## 问题原因

通过对比 my-admin 项目的实现，发现 graduation-system 存在以下问题：

### 1. 后端返回完整 URL

**问题文件**：`graduation-api/src/main/java/com/lw/graduation/api/service/file/impl/UnifiedFileUploadServiceImpl.java`

**问题描述**：
- `buildResult()` 方法中同时返回了 `storedPath`（相对路径）和 `url`（完整 URL）
- 前端直接使用了 `url` 字段，导致保存了完整路径

**当前实现**：
```java
return FileUploadResultVO.of(
    originalFilename,
    file.getSize(),
    file.getContentType(),
    storedPath,           // 相对路径：avatar/123/avatar.jpg
    fileStorageService.getUrl(storedPath),  // 完整 URL：/files/avatar/123/avatar.jpg
    extension,
    DateUtil.now()
);
```

### 2. 前端使用完整 URL

**问题文件**：`graduation-system-vue/src/components/common/FileUpload.vue`

**问题描述**：
- 前端在 `handleUpload()` 方法中使用了 `response.data.url`
- 还调用了 `getFileUrl()` 再次包装，可能导致 URL 重复拼接

**修复前的错误代码**：
```typescript
const fileUrl = response.data.url || response.data.name
existingFile.url = getFileUrl(fileUrl)  // ❌ 错误：再次包装完整 URL
```

## 修复方案

### 方案核心：使用相对路径存储

#### 1. 后端保持不变

后端 `FileStorageService.getUrl()` 返回的是相对路径（如 `/files/avatar/123/avatar.jpg`），这个设计是正确的，不需要修改。

**LocalFileStorageServiceImpl.getUrl()**：
```java
@Override
public String getUrl(String filePath) {
    if (filePath == null || filePath.trim().isEmpty()) {
        return null;
    }
    return urlPrefix + "/" + filePath;  // 返回：/files/avatar/123/avatar.jpg
}
```

#### 2. 前端修改：使用 storedPath

**修改文件**：`graduation-system-vue/src/components/common/FileUpload.vue`

**修改内容**：
```typescript
// ✅ 正确：优先使用 storedPath（相对路径）
const fileUrl = response.data.storedPath || response.data.url || response.data.name
existingFile.url = fileUrl  // 直接保存相对路径，不再调用 getFileUrl()
```

**修改说明**：
- 优先使用 `storedPath` 字段（相对路径）
- 直接保存相对路径，不再调用 `getFileUrl()` 包装
- 这样保存到数据库的就是 `avatar/123/avatar.jpg` 这样的相对路径

#### 3. 前端显示时转换 URL

**修改文件**：`graduation-system-vue/src/utils/utils.ts`

**修改内容**：
```typescript
export const urls2FileList = (url: string | null | undefined): FileItem[] => {
  if (!url || typeof url !== 'string') {
    return []
  }
  return url
    .split(',')
    .map((item) => item.trim())
    .filter((item) => item)
    .map((item) => ({
      name: item,
      // ✅ 只在需要时才添加 BASE_URL 前缀
      url: item.startsWith('/') ? normalizePath(constants.BASE_URL, item) : item,
    }))
}
```

**修改说明**：
- 在显示时（从数据库读取后）才将相对路径转换为完整 URL
- 判断逻辑：如果路径以 `/` 开头，则添加 `BASE_URL` 前缀
- 这样可以正确处理相对路径和完整 URL 两种情况

## 修复效果

### 修复前

**数据库存储**：
```
http://127.0.0.1:8080/files/avatar/2011317294235017217/avatar.jpg
```

**问题**：
- ❌ 开发环境：可能正常工作，但 URL 冗长
- ❌ 生产环境：无法访问，因为指向开发环境地址
- ❌ 数据迁移：无法在不同环境间迁移数据

### 修复后

**数据库存储**：
```
/files/avatar/2011317294235017217/avatar.jpg
```

**优势**：
- ✅ 开发环境：前端通过 `BASE_URL` 自动拼接为完整 URL
- ✅ 生产环境：前端自动使用生产环境的 `BASE_URL`
- ✅ 数据迁移：数据库数据可以在任何环境使用

## 完整流程

### 上传流程

```
用户选择文件
  ↓
FileUpload.vue 组件上传
  ↓
后端返回 storedPath: /files/avatar/123/avatar.jpg
  ↓
前端保存相对路径到 fileList
  ↓
表单提交时保存到数据库：/files/avatar/123/avatar.jpg
```

### 显示流程

```
从数据库读取 avatar: /files/avatar/123/avatar.jpg
  ↓
urls2FileList() 转换
  ↓
添加 BASE_URL 前缀：http://生产环境地址/files/avatar/123/avatar.jpg
  ↓
Avatar.vue 组件显示
```

## 总结

本次修复遵循了**"存储相对路径，显示时转换"**的原则，确保了：

1. **环境无关性**：数据库存储的路径与环境无关
2. **可移植性**：数据可以在不同环境间迁移
3. **灵活性**：前端可以根据当前环境自动使用正确的 `BASE_URL`

**关键修复点**：
- ✅ 前端上传时使用 `storedPath`（相对路径）
- ✅ 前端显示时通过 `urls2FileList()` 转换为完整 URL
- ✅ 后端保持不变，继续提供 `storedPath` 和 `url` 两个字段
