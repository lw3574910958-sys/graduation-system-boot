# 头像文件名格式修复说明

## 问题描述

用户发现头像上传后，存入数据库的文件名是 `avatar.jpg`，而不是预期的时间戳格式（如 `20260308001234567.jpg`）。

**当前实现**：
```
数据库存储路径：avatar/用户 ID/avatar.jpg
```

**期望实现**：
```
数据库存储路径：avatar/用户 ID/20260308001234567.jpg
```

## 问题根源分析

### 代码调用链

```
用户上传头像
  ↓
UnifiedFileUploadServiceImpl.uploadAvatar(file, userId)
  ↓
fileStorageService.store(file, "avatar/用户 ID", "avatar")  ← 传入第三个参数 "avatar"
  ↓
LocalFileStorageServiceImpl.generateFilenameWithTimestamp("avatar", extension)
  ↓
返回 "avatar.jpg"  ← 因为 customName 不为空
```

### 关键代码

#### 1. UnifiedFileUploadServiceImpl.uploadAvatar() - 问题代码

**修改前**：
```java
@Override
public FileUploadResultVO uploadAvatar(MultipartFile file, Long userId) throws IOException {
    // ... 验证逻辑 ...
    
    // 存储头像文件
    String category = "avatar/" + userId;
    String storedPath = fileStorageService.store(file, category, "avatar");  // ❌ 传入 "avatar"
    
    return buildResult(file, storedPath);
}
```

#### 2. LocalFileStorageServiceImpl.generateFilenameWithTimestamp() - 生成逻辑

```java
private String generateFilenameWithTimestamp(String customName, String extension) {
    if (customName != null && !customName.trim().isEmpty()) {
        // 如果指定了自定义文件名，使用自定义名称
        return customName + "." + extension.toLowerCase();  // 返回 "avatar.jpg"
    }
    // 使用时间戳格式：yyyyMMddHHmmssSSS
    String timestamp = DateUtil.format(new java.util.Date(), "yyyyMMddHHmmssSSS");
    return timestamp + "." + extension.toLowerCase();  // 返回 "20260308001234567.jpg"
}
```

**问题分析**：
- 当传入第三个参数 `"avatar"` 时，`customName` 不为空
- 方法返回 `customName + extension`，即 `avatar.jpg`
- 不会使用时间戳格式生成文件名

## 修复方案

### 核心思路

修改 `uploadAvatar()` 方法，不传第三个参数（自定义文件名），让 `store()` 方法自动生成时间戳格式的文件名。

### 修改内容

**修改文件**：`graduation-api/src/main/java/com/lw/graduation/api/service/file/impl/UnifiedFileUploadServiceImpl.java`

**修改后的代码**：
```java
@Override
public FileUploadResultVO uploadAvatar(MultipartFile file, Long userId) throws IOException {
    if (file == null || file.isEmpty()) {
        throw new IllegalArgumentException("头像文件不能为空");
    }

    // 获取文件名
    String originalFilename = file.getOriginalFilename();
    // 获取文件扩展名
    String extension = getFileExtension(originalFilename);

    // 验证是否为图片类型
    FileFormatType fileType = FileFormatType.getByExtension(extension);
    if (fileType == null || fileType.getCategory() != FileFormatType.Category.IMAGE) {
        throw new IllegalArgumentException("仅支持图片格式文件");
    }

    // 验证文件大小（头像限制为 2MB）
    if (file.getSize() > 2 * 1024 * 1024) {
        throw new IllegalArgumentException("头像文件大小不能超过 2MB");
    }

    // 存储头像文件（使用时间戳生成文件名，不使用自定义名称）
    String category = "avatar/" + userId;
    String storedPath = fileStorageService.store(file, category);  // ✅ 不传第三个参数
    
    // 构建返回结果
    return buildResult(file, storedPath);
}
```

**修改对比**：
```diff
- String storedPath = fileStorageService.store(file, category, "avatar");
+ String storedPath = fileStorageService.store(file, category);  // ✅ 不传第三个参数
```

## store() 方法重载说明

`FileStorageService.store()` 提供了两个重载方法：

### 方法 1：不指定文件名（自动生成时间戳格式）

```java
String store(MultipartFile file, String category) throws IOException;
```

**调用示例**：
```java
// 内部会调用 generateFilenameWithTimestamp(null, extension)
// 生成时间戳格式文件名
String storedPath = fileStorageService.store(file, "avatar/用户 ID");
// 返回：avatar/用户 ID/20260308001234567.jpg
```

### 方法 2：指定自定义文件名

```java
String store(MultipartFile file, String category, String filename) throws IOException;
```

**调用示例**：
```java
// 内部会调用 generateFilenameWithTimestamp("avatar", extension)
// 生成自定义文件名
String storedPath = fileStorageService.store(file, "avatar/用户 ID", "avatar");
// 返回：avatar/用户 ID/avatar.jpg
```

**问题**：

**上传流程**：
```
用户上传 test.jpg
  ↓

  ↓

  ↓

  ↓
数据库存储：avatar/123/20260308001234567.jpg
```

**优势**：
- ✅ 每次上传都有唯一的文件名（基于时间戳）
- ✅ 保留所有历史头像记录
- ✅ 便于追溯和管理
- ✅ 避免并发冲突

## 文件名格式说明

### 时间戳格式

**格式**：`yyyyMMddHHmmssSSS`

**示例**：
- `20260308001234567.jpg` - 2026 年 3 月 8 日 00 点 12 分 34 秒 567 毫秒
- `20260308145623890.png` - 2026 年 3 月 8 日 14 点 56 分 23 秒 890 毫秒

### 组成部分

| 部分 | 含义 | 位数 | 示例 |
|-----|------|-----|------|
| yyyy | 年 | 4 | 2026 |
| MM | 月 | 2 | 03 |
| dd | 日 | 2 | 08 |
| HH | 时 | 2 | 00 |
| mm | 分 | 2 | 12 |
| ss | 秒 | 2 | 34 |
| SSS | 毫秒 | 3 | 567 |
| extension | 扩展名 | 可变 | .jpg |

**总长度**：17 位数字 + 扩展名（通常 3-4 位）

## 注意事项

### 1. 文件清理

由于每次上传都会生成新文件，需要定期清理废弃的头像文件：

**建议方案**：
- 在删除用户时，同步删除该用户的所有头像文件
- 提供定时任务，清理数据库中不再引用的头像文件

### 2. 存储空间

**估算**：
- 假设每个头像平均 200KB
- 每个用户平均上传 10 次
- 1000 个用户

**所需空间**：
```
200KB × 10 × 1000 = 2,000,000 KB ≈ 1.9 GB
```

**建议**：
- 定期检查磁盘空间
- 设置合理的头像大小限制（当前为 2MB）
- 考虑实施自动清理策略

### 3. 并发安全

虽然使用时间戳可以极大降低重名概率，但在极高并发场景下（同一毫秒内上传），仍可能产生重名。

**解决方案**：
- 当前实现已使用毫秒级时间戳，概率极低
- 如需更高安全性，可以使用 UUID：`IdUtil.fastSimpleUUID() + "." + extension`

## 总结

本次修复通过移除 `uploadAvatar()` 方法中传入的自定义文件名参数，使头像上传功能使用时间戳格式生成文件名。

**核心改进**：
- ✅ 文件名格式：`yyyyMMddHHmmssSSS.extension`
- ✅ 唯一性保证：毫秒级时间戳确保文件名不重复
- ✅ 历史记录保留：每次上传都生成新文件，不会被覆盖
- ✅ 可追溯性：通过文件名即可知道上传时间

**适用场景**：
- 需要保留历史头像记录的系统
- 需要追溯用户头像变更历史
- 避免文件覆盖导致的数据丢失

现在头像上传会使用标准的时间戳格式生成文件名了！🎉
